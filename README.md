# Willowhush — *Quiet practices for a gentler mind*

A static meditation & mindfulness blog. Plain HTML, CSS and vanilla JS. No frameworks.

**Live site:** https://elrond44.github.io/willowhush-/ (GitHub Pages, served from the `docs/` folder on `main`)

## The finished site is in `docs/`
Open `docs/index.html` in a browser, or serve it locally:

    python3 -m http.server 8000 -d docs   # then visit http://localhost:8000

All internal links and asset references are relative, so the site works under the `/willowhush-/` subpath on GitHub Pages
(and at a domain root or any other subpath). Keep it that way: never write root-absolute URLs like `/assets/...`.

## Update the live site
    # 1. edit files in src/, build.py or practices.py
    python3 build.py                      # 2. rebuild docs/
    python3 -m http.server 8000 -d docs   # 3. (optional) preview locally
    git add -A && git commit -m "Describe the change"
    git push origin main                  # 4. GitHub Pages redeploys automatically (about a minute)

Always commit the rebuilt `docs/` together with the source change; Pages serves `docs/` as-is (`docs/.nojekyll` disables Jekyll).

## Editing
`docs/` is generated by a tiny standard-library Python script, so the header and footer are shared across pages:

    python3 build.py      # rebuilds docs/ from src/

- `build.py`: page templates, site settings (name, tagline, URL), and the post list (titles, categories, dates, images)
- `src/posts/*.html`: article bodies
- `ebook.py`: the Ebook page, home-page feature and journal promo card (book data, chapters, quotes, FAQ, buy box)
- `practices.py`: markup for the interactive tools (timer, body scan, grounding, loving-kindness, breathing circle) and the guided-session data (captions + timings)
- `src/assets/css/style.css`, `src/assets/js/main.js`: styles and core interactions (scroll reveals, mobile menu, blog filters, breathing widget, placeholder forms)
- `src/assets/js/practice.js`: interactive practices, the guided video player, and the exercise checklists (ticks saved in localStorage)
- `src/assets/video/`: looping ambient clips (H.264 MP4 + VP9 WebM, 720p, ~20 s seamless forward/back loops) and posters
- `src/assets/audio/`: per session, `<id>-voice.mp3` (narration, `make_narration.py`) and `<id>-music.mp3` (ambient music, `make_music.py`)
- `src/assets/images/`: AI-generated original images (WebP, plus `-sm` thumbnails; `og-image.jpg` for social cards)

To add a post, write `src/posts/<slug>.html`, add an entry to `POSTS` in `build.py` (newest first; the first post is featured on the journal page), and rebuild.

### Inside a post
- Embed a tool with an HTML comment: `<!--tool:timer-->`, `<!--tool:bodyscan-->`, `<!--tool:grounding-->`, `<!--tool:kindness-->`, `<!--tool:breathe-->`, or a guided video with `<!--tool:session:winddown-->` (any session id).
- Add an exercise checklist:

      <section class="exercise" data-exercise="unique-id"><span class="eyebrow">Exercise</span><h2>Title</h2><p>Intro</p>
        <ol class="checklist"><li><strong>Step.</strong> Details</li>...</ol></section>

  JavaScript turns each item into a tickable checkbox, remembers ticks per device, and adds "Print this exercise" / "Clear ticks".

### Guided sessions
Edit captions and timings in `SESSIONS` (practices.py). Captions also serve as the narration script. After changing them, re-render:

    KOKORO_DIR=/path/to/kokoro python3 make_narration.py   # voice -> src/assets/audio/<id>-voice.mp3 + narration_timing.json
    python3 make_music.py                                  # music -> src/assets/audio/<id>-music.mp3 (python3 make_music.py 60 = quick preview)
    python3 build.py

- **Voice:** [Kokoro-82M](https://huggingface.co/hexgrad/Kokoro-82M) (model weights and voices licensed **Apache-2.0**, commercial use allowed),
  run offline on CPU via `kokoro-onnx` (MIT) with `kokoro-v1.0.onnx` + `voices-v1.0.bin` from the kokoro-onnx releases. Voice **`af_heart`**,
  speed 0.82, spoken sentence by sentence with ~0.4 s pauses at commas and ~1 s between sentences, starting 0.8 s after each caption cue.
  Loudness-normalised to -16 LUFS (true peak -1.5 dB), 64 kbps mono MP3. `make_narration.py` warns if a line would overrun the next cue.
  (Phonemisation uses espeak-ng via `phonemizer`/`espeakng-loader`, GPL-3.0 tools used only at build time; nothing from them ships on the site.)
- **Music:** composed and synthesized for Willowhush by `make_music.py` (numpy/scipy, seeded, no samples): soft detuned additive pads
  with slowly drifting harmonics, a quiet root/fifth drone, sparse singing-bowl strikes (and felt-piano notes in body scan and
  loving-kindness), synthetic reverb, gentle high/low-pass. One palette per session (breath: D major; body scan: G; wind-down: low F;
  loving-kindness: C). Original work owned by the site, no third-party licence. -28 LUFS, 96 kbps stereo MP3, same length as the session,
  6 s fade-in / 8 s fade-out.
- **Player:** one session clock drives captions, voice and music (two `<audio>` elements, both started from the user's Begin/Play tap
  so iOS allows playback, re-synced on seek/pause/resume). Voice and Music are both ON by default (`wh-voice-v2`, `wh-music`, `wh-music-vol` in
  localStorage). Music goes through a Web Audio gain node (volume slider, default 0.8, ducked a further ~4 dB while the voice speaks,
  using `narration_timing.json`) so music sits roughly 13-18 dB under the voice; on older iOS without `navigator.audioSession` the music plays
  at its fixed level and the slider is hidden. If the voice file can't load, the Voice toggle falls back to the browser's speechSynthesis.
- `tools/mix_sample.py <id> <from> <to> out.mp3` renders a premixed voice+music excerpt (same levels as the player) for listening samples.

## Ebook: *Good Vibrations* (pay what you want)
The Ebook page (`ebook.html`, built by `ebook.py`) sells the 52-page PDF *Good Vibrations* on a pay-what-you-want basis
(suggested $5 / $9 / $15 or a custom amount, minimum $1). It is linked from the main nav, the footer, a feature section on the
home page, and a promo card at the end of every journal post and on the journal index.

**Never commit the full book.** Only the free sample is public: `src/assets/ebook/good-vibrations-sample.pdf`
(book pages 1-9: cover, title page, contents, introduction and all of Chapter 1, plus a closing "get the full book" page).
`.gitignore` ignores every other `*.pdf`, and `build.py` refuses to build if any other PDF ends up in `docs/`.

### Connecting checkout
1. Create a pay-what-you-want product on your platform and upload the **full** PDF there (not to this repo):
   - **Gumroad**: set the price to $1 and tick "Allow customers to pay what they want" (suggested price $9).
   - **Lemon Squeezy**: product pricing "Pay what you want", minimum $1, suggested $9.
   - **Payhip**: pricing "Pay what you want", minimum $1.
   - **Ko-fi Shop**: add a digital product and enable "pay what you want" with a $1 minimum.
2. Copy the product's public link and paste it into `build.py`:

       EBOOK_CHECKOUT_URL = "https://yourname.gumroad.com/l/good-vibrations"

3. Optional: if your platform supports pre-filling the amount through a URL query parameter, set `EBOOK_PRICE_PARAM`
   (e.g. `"price"`) and the reader's chosen amount is appended to the link. Check your platform's docs first; when in doubt
   leave it empty, since every platform above lets the buyer type the amount at checkout.
4. `python3 build.py`, commit, push.

While `EBOOK_CHECKOUT_URL` is empty, the buy box shows a disabled "Checkout coming soon" state and offers the free sample
instead, so there is never a broken buy link. Suggested amounts, minimum and the book details live in `EBOOK` in `ebook.py`.

### Regenerating the ebook assets
If the book changes, rebuild the sample, cover, social card and page previews from the full PDF (kept outside the repo):

    python3 tools/make_ebook_assets.py /path/to/good-vibrations.pdf   # needs poppler-utils + Pillow (Playwright optional)
    python3 build.py

## Notes
- The public base URL is `https://elrond44.github.io/willowhush-/` (`SITE["url"]` in build.py, and in `src/robots.txt`). Canonical/OG URLs and `sitemap.xml` use it; change both if you move to a custom domain.
- The newsletter and contact forms are UI placeholders. They validate input and show a thank-you message, but send nothing. Connect them to a provider (Buttondown, Formspree, Netlify Forms...) when ready.
- Fonts load from Google Fonts (Cormorant Garamond + Inter).
